# Publish one Instance through multiple distribution paths

Stash publishes the same server core and web application as the multi-architecture OCI image `ghcr.io/djerayane/stash` and as checksummed self-contained Instance bundles that require no separately installed runtime or database. The supported team and production baseline remains Docker Compose with one Stash application container and PostgreSQL, and a fresh checkout supplies clearly marked localhost-only defaults whose published port is exactly `127.0.0.1:${STASH_PORT:-3000}:3000`, so `docker compose up -d` starts an evaluable Instance without exposing it on every interface. The self-contained distribution runs the same domain and HTTP capabilities against an embedded, filesystem-persistent PostgreSQL-compatible engine, stores Attachments beneath one operator-selected data directory, binds to loopback by default, and can migrate its complete Instance into the standard PostgreSQL deployment without invoking Docker. Because ADR-0032 keeps `INSTANCE_MASTER_KEY` outside the database, migration requires the operator either to provision the source key at the destination or to supply separate source and destination keys for explicit re-encryption; the migration never copies or invents that secret, and acceptance covers accounts, Organizations, built-in Roles and memberships, identities, Workspaces, history, audit data, configuration, Attachments, checksums, authentication, and authorization. It is a distribution and storage adapter, not a separate local-only product. Canonical semantic-version releases may also produce signed Expo mobile artifacts that connect directly to a Member-supplied HTTPS Instance; Android publication does not depend on optional iOS signing capability. One complete release-quality gate verifies every available artifact path, and every publisher directly depends on it as each distribution path is added. A Git tag selects a source revision but is not itself treated as immutable: tag-only preflight checks collision and ref integrity, while recorded OCI and SHA-256 digests remain the permanent artifact identities even if a tag is later moved.
