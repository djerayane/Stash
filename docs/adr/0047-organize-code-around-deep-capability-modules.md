# Organize code around deep capability modules

Stash will replace its flat, highly coupled server and web organization with aligned capability modules such as knowledge authoring, work planning, identity and access, development integration, and Instance operations. The migration remains behavior-preserving and incremental: first divide the universal Postgres adapter into focused adapters over one private database kernel, then let capability modules own behavior, route registration, and focused interface tests behind compact interfaces; web modules mirror product capabilities without forcing identical internals, root tests remain only for true adapter and cross-module verification, and workspace packages contain only contracts or behavior reused by multiple real clients. Delivery uses substantial end-to-end capability slices rather than microscopic file moves or one-file pull requests, so each review and CI run buys a meaningful reduction in coupling or a complete usable workflow.
