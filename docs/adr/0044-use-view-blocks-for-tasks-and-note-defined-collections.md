# Use View Blocks for Tasks and Note-defined Collections

Notes may define Collections whose initial property types cover text, number, checkbox, date and time, single-select, multi-select, person, URL, Attachment, and direct relations to Collection records, Notes, Tasks, or Projects, while Tasks remain distinct actionable Workspace objects. One View Block system presents either source through boards, tables, lists, calendars, and later view types; the Block owns filters and presentation rather than the displayed records, preserving canonical Tasks while enabling Notion-like structured knowledge that is not mislabeled as work. A Collection remains owned by its defining Note through archive; trash or permanent deletion requires moving the Collection to another Note or explicitly deleting it after previewing affected View Blocks and relations. Formulas, relation rollups, generated values, location, and plugin-defined persisted property types are deferred until the Collection identity, relation, portability, and error models are proven.
