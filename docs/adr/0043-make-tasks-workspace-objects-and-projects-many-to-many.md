# Make Tasks Workspace objects and Projects many-to-many

Tasks belong to a Workspace and may be associated with zero, one, or several nested Projects, rather than being owned by exactly one Project. Subtasks are canonical Tasks with one parent and independent Project associations; Project parents aggregate only descendants and content visible to the current Member, while boards and other Task views display and manipulate the same canonical Tasks without copying or overriding their fields. Access through any associated Project reveals the Task but not inaccessible Project associations or related content. Each Project uses its own prefix and sequence to assign a key when a Task is associated, regardless of Project nesting; removing an association permanently reserves its key as an alias, while Projectless and Project-agnostic views need no human-readable key. This supersedes the Project-ownership assumptions in ADR-0006 and ADR-0035.
